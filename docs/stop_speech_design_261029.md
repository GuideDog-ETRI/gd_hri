- 작성: 2026-10-29
- 상태: **구현 완료, 실제 음성 연동 시험 전** (2026-10-30) — 13장 참고
- 범위: gdh 음성 인식·image_ai_node(Thor gdh), VLM3 guidedog-cli(Thor gd_vlm), TTS 서버(u-pc 192.168.2.12)

## 1. 목표

로봇이 말하는 중에 사용자가 "조용히 해"라고 하면 바로 조용해진다. **VLM이 답을 생성해 내보내는 중이어도** 멈춘다.

1. 음성 인식기가 바로 알아듣고 TTS 서버와 VLM에 정지를 알린다.
2. TTS 서버는 수신 쓰레드에서 세대 번호를 올려, 쌓인 말을 모두 버리고(합성·재생 워커가 꺼낼 때 건너뜀) 말하던 문장도 끊는다.
3. VLM은 지금 만드는 답의 남은 문장을 TTS 로 보내지 않는다 (생성을 멈추거나, 생성은 하되 보내지 않음 — 7장).

### 2.2 큐가 있는 곳

| 위치 | 큐 | 내용 |
|---|---|---|
| image_ai_node | 없음 | 요청을 받는 즉시 VLM 으로 보냄 |
| VLM SUB `:5555` 수신 버퍼 | ZMQ 내부 버퍼 | VLM 이 답을 만드는 동안 들어온 요청이 쌓였다가 하나씩 처리됨 (예: "지금 상황 어때" 두 번 → 답 두 번) |
| VLM → TTS | **없음** | 문장·태그 하나가 끝나면 바로 전송. 답 하나가 여러 메시지로 나뉘어 생성되는 동안 계속 들어옴 (최대 512 토큰 또는 `</recommend>` 까지) |
| TTS 서버 | `message_queue`, `audio_queue` | 합성 대기 텍스트, 재생 대기 음성 조각 — **말이 쌓이는 곳은 여기뿐** |

### 2.3 TTS 서버만으로는 VLM을 막을 수 없는 이유

- 4070 메시지에는 보낸 쪽이나 "어느 답의 몇 번째 조각"인지 정보가 없다.
- 그래서 서버는 VLM 이 이어서 보내는 조각과 gdm 위험 안내 같은 새 말을 구분하지 못한다.
- 서버 혼자 막으려면 "정지 후 몇 초 동안 모두 무시"밖에 없는데, 그러면 위험 안내도 묻힌다 (무시 구간은 두지 않기로 함).
- → **VLM 쪽에서 그 답의 남은 문장이 나가지 않게** 한다 (7장). VLM 은 답이 언제 끝나는지 정확히 안다.

### 2.4 서버에 이미 있는 `@` 명령 (`music_player.py`, `README.robot_pc.md`)

- `@play 이름` : `~/Music` 의 효과음·음악 재생 (notify, bark, boost, gdm, poweroff …)
- `@stop` : **음악 정지** (Thor 쪽에서 보내는 곳은 없음)
- → `@stop` 은 이미 쓰이므로 발화 정지는 새 코드 **`@quiet`** 를 쓴다.

## 3. 전체 흐름

```
사용자 "조용히 해"
   │  말 끝 0.8초 조용함 감지 + Whisper 약 0.3초
   ▼
[gdh STT] 인식 문장에 정지 단어가 들어 있음? ── 예 ──┬──────────────────────────────┐
                                                    │ ① /GDH_speak_text "@quiet"   │ ② /GDH_quiet (ROS 토픽)
                                                    ▼                              ▼
                                         [gdh msg_to_audio]               [gdh image_ai_node]
                                          ZMQ PUSH → 4070                  ZMQ PUB :5556 "@quiet"
                                                    │                              ▼
                                                    │                     [VLM guidedog-cli] 답을 만드는 중이면
                                                    │                      · 생성 중단 (남은 문장 안 보냄), 기다리던 요청 버림
                                                    │                      · 다음 답부터는 평소대로
                                                    │                      · ③ 자기 PUSH 로 "@quiet" → 4070 (한 번)
                                                    ▼                              ▼
                              [TTS 서버] 수신 루프: "@quiet" → 세대 번호 +1 (큐에 넣지 않음)
                                         tts_worker: 옛 세대 메시지는 합성하지 않고 버림 (조각마다 확인)
                                         audio_worker: 옛 세대 조각은 버림, 재생 블록(약 21ms)마다 확인 → 페이드아웃
```

- ① 은 지금 나오는 말과 이미 쌓인 말(VLM·gdm·gds·gdh 모두)을 바로 끊는다.
- ② 는 VLM 이 앞으로 보낼 말을 막는다.
- ③ 은 ① 과 ② 사이(수십 ms)에 VLM 이 보낸 마지막 조각을 지운다.
  - VLM 이 조각을 보낸 소켓과 같은 소켓으로 보내므로 순서가 보장된다. 그래서 그 조각은 반드시 ③ 보다 먼저 서버 큐에 들어가 있다.

## 4. 메시지 규약

| 통로 | 형식 | 내용 |
|---|---|---|
| 4070 (기존) | `float32 속도(4바이트)` + `UTF-8 "@quiet"` | 쌓인 말을 모두 버리고 말하던 문장을 끊음. 속도 값 무시. 인자 없음 |
| ROS `/GDH_quiet` (신규) | `std_msgs/String`, data = 인식 원문 | STT → image_ai_node. 원문은 로그용 |
| 5556 (신규) | ZMQ PUB/SUB 1 프레임 `"@quiet"` | image_ai_node(bind) → VLM(connect). 지금 답의 TTS 전송 중단 요청 |

- 정지한 뒤 새로 도착하는 말은 평소처럼 말한다 (정지 후 무시 구간 없음).
- 음악·효과음(`@play`)은 건드리지 않는다 (별도 재생기, 끄려면 `@stop`).

## 6. STT 변경 설계 (gdh `speech_to_cmd_by_whisper.py`)

### 6.1 설정 — `models/gdh_config.yaml` 의 `STT:` 아래

```yaml
  # [2026-10-29] "조용히 해": 인식 문장에 words 중 하나가 들어 있으면 TTS 서버에 code 를 보내고(쌓인 말 삭제·말하던 문장 끊기)
  #   /GDH_quiet 를 발행해 VLM 이 지금 답의 남은 문장을 내보내지 않게 함 (192.168.2.12 tts-kor-server.py 에 @quiet 처리 필요)
  stop_speech:
    enable: False     # TTS 서버 작업이 끝난 뒤 True (그 전에 켜면 서버가 "@quiet" 를 글자로 읽어 버림)
    words: ["조용히해", "조용히하세요", "조용히좀해"]   # 공백 무시, 인식 문장에 들어 있으면 정지 (호출어·군말이 붙어도 됨)
    code: "@quiet"
```

### 6.2 코드 — `SpeechToCmd`

- `__init__` (대화 모드 설정을 읽는 곳 바로 다음)
  - `stop_speech` 설정을 읽는다. 항목이 없으면 `enable: False` 로 본다.
  - 단어는 공백을 지워 둔다. 시작할 때 로그로 출력한다.
  - `/GDH_quiet` (`std_msgs/String`) 발행자를 만든다.
- `_listen_and_publish()` — 인식 결과 보정(`stt_key.replace("지금의", "지금")`) 바로 다음, **대화 모드 시작/종료 검사보다 먼저**:
  - 정지 단어 중 하나가 `stt_key` 에 들어 있으면
    1. `self._speak(code)` → `/GDH_speak_text` (응답은 기다리지 않음, 기존 함수 그대로)
    2. `self._speak("@play notify")` — 다른 명령과 같은 인식 알림음 (2026-10-30 사용자 요청). `@quiet` 다음에 보냄
    3. `/GDH_quiet` 발행 (data = 인식 원문)
    4. 로그 `[STOP] “원문” -> @quiet`
    5. `continue` (명령 매칭·대화 질문으로 넘기지 않음)
- 하지 않는 것
  - 대화 모드는 그대로 둔다 (끄려면 "대화 종료").
  - `/GDH_user_cmd` 를 발행하지 않는다.
- 맨 앞에서 검사하는 이유: 대화 모드에서는 명령이 아닌 문장이 VLM 질문으로 가므로, 늦게 검사하면 "조용히 해"가 VLM 질문이 되어 또 답을 말하게 된다.
- 기존 명령은 "완전히 같아야" 인식되지만, 정지 단어는 "들어 있으면" 인식한다. "에디야 조용히 해", "아 조용히 해 좀" 같은 말도 잡기 위해서다.

### 6.3 인식 보강 (선택, 시험 후 결정)

- `openai_whisper.INITIAL_PROMPT` 에 "조용히 해." 를 넣으면 더 잘 알아들을 수 있다.
  - 다만 힌트 문장은 잡음에서 지어낸 문장으로 나올 수 있다(`MIN_AVG_LOGPROB` 로 대부분 걸러짐). 넣는다면 로그를 확인한다.
- 실제 로그에서 잘못 들은 형태(예: "조용이 해")가 보이면, 기존 보정 방식(`stt_key.replace`)으로 추가한다.

## 7. VLM 설계 — 지금 답의 남은 문장 막기

### 7.1 언제까지 막나: "정지 요청을 받은 그 답이 끝날 때까지"

- VLM 은 요청(프레임 + 질문) 하나에 답 하나를 만든다 (`main` 루프 1회 = `generate_and_publish` 1회).
- 정지 범위를 "정지 요청을 받은 그 답"으로 정하면, 시간으로 짐작하지 않아도 VLM 이 경계를 정확히 안다.
  - **답 시작** (`receive_frame` 다음, `eval_user` 전): 제어 소켓에 쌓인 옛 `@quiet` 를 버리고 정지 표시를 끈다.
    - 이전에 온 정지 요청이 새 답으로 넘어오지 않는다.
  - **답을 만드는 중** `@quiet` 수신: 이 답에만 적용한다.
  - **답 끝** (끝 토큰, `</recommend>`, 최대 토큰 수): 정지 표시가 자연히 풀린다. 다음 질문의 답은 평소대로 말한다.
- 쉬는 중에 `@quiet` 가 오면: 막을 답이 없으므로 아무 일 없다 (다음 답을 시작할 때 버려짐).
- 이미지·프롬프트 처리(prefill) 중에 `@quiet` 가 오면: 첫 토큰 전에 확인하므로 그 답 전체가 대상이다 (아무것도 나가지 않음).

### 7.2 방식 비교

| | **A. 생성 중단 (채택)** | B. 생성 계속, 전송만 안 함 (미채택) |
|---|---|---|
| 동작 | 다음 토큰에서 생성을 멈춤 | 끝까지 생성하고 `emit()` 에서 ZMQ 전송만 건너뜀 (로그는 남김) |
| 다음 질문 반응 | 바로 처리 | 남은 생성이 끝날 때까지 기다림 (남은 답 길이에 따라 수 초) |
| GPU | 바로 쉼 | 남은 토큰만큼 계속 사용 |
| 로그 | 멈춘 곳까지만 남음 | 답 전체가 남음 |
| 고칠 곳 | 토큰 루프 종료 + 마지막 flush 생략 | `speech_parser` 에 전송 차단 표시 |
| 공통 | 제어 소켓 확인, 답 시작 때 초기화, ③ `@quiet` | 같음 |

- **A 로 결정** (2026-10-30). 사용자가 멈추라고 한 답을 끝까지 만들 이유가 없고, B 는 그동안 다음 질문이 밀린다.

### 7.3 image_ai_node (`image_ai_node_fast.py`)

- 설정 `gdh_config.yaml` 의 vlm 항목에 `zmq_ctl_addr: "tcp://*:5556"` 를 추가한다. 이 주소에 PUB 소켓을 bind 한다.
- `/GDH_quiet` 를 구독하고, 받으면 5556 으로 `"@quiet"` 1 프레임을 보낸다.
  - VLM 이 연결되어 있지 않으면 PUB 이 그냥 버린다. 기다리거나 다시 보내지 않는다.
- 로그 `[QUIET] VLM 에 정지 요청 (“원문”)`

### 7.4 VLM guidedog-cli (`guidedog-cli.cpp`, `run_vlm3.sh`)

- 옵션 `--zmq-ctl <주소>` 를 추가한다.
  - 기본값은 없음(꺼짐)이라 지금 동작과 같다. `run_vlm3.sh` 에 `--zmq-ctl tcp://localhost:5556` 를 추가한다.
  - SUB 소켓으로 connect 하고 모두 구독한다.
- 답 시작 때 초기화한다 (7.1).
- **토큰 생성 루프** (`generate_and_publish`): 토큰마다 제어 소켓을 기다리지 않고(`dontwait`) 확인한다.
- **`@quiet` 를 받으면** (그 답에서 한 번만)
  - 루프를 끝낸다. 마지막 `parser.update(true)` 는 생략한다 (반쯤 만들어진 문장을 보내지 않음).
  - 요청 소켓(`:5555`)에 쌓여 있던 요청(정지 전에 들어와 기다리던 질문)을 모두 버린다 (멀티파트 끝까지, 2026-10-30 결정).
  - TTS 로 `"@quiet"` 를 보낸다 (3장 ③, 자기 PUSH 소켓, 한 번).
    - 정지 요청을 받기 직전에 보낸 조각을 서버에서 지우기 위해서다.
  - 로그 `[quiet] 토큰 N개째에서 생성 중단, 보낸 조각 M개, 버린 요청 K개`
- 기존 SIGINT 처리(생성 중이면 생성만 멈춤)는 쓰지 않는다.
  - 생성이 막 끝난 순간에 신호가 오면 프로세스가 종료된다.
  - 반쯤 만들어진 문장도 보내 버린다.
- 수정 후 `llama-guidedog-cli` 를 다시 빌드한다.

### 7.5 VLM 쪽 반응 시간

- 정지 요청을 다음 토큰에서 확인한다 (토큰 하나 시간, 수십 ms). 그때부터 아무것도 보내지 않는다.

## 8. 반응 시간 (추정)

| Whisper large-v3-turbo | 중앙값 0.26초 / 90% 0.37초 | gdh 로그 400건 실측 (2026-10-29) |

→ "조용히 해"를 다 말하고 **약 1.1~1.3초 뒤** 조용해질 것으로 예상한다.

## 9. 알려진 동작·위험

1. **로봇 스피커 소리가 마이크로 들어온다.** 오늘(10-29) 로그에서 "횡단보도에 도착했습니다", "링크에 다시 연결되었습니다" 같은 로봇 안내가 받아쓰기되었다.
   - 로봇이 쉬지 않고 말하는 동안에는 "말 끝(0.8초 조용함)"이 잡히지 않는다. 그러면 녹음이 `RECORD_TIMEOUT`(4초)까지 이어져 정지가 최대 약 4초 늦어지고, 로봇 말과 섞여 받아쓰기될 수 있다. → **시험에서 꼭 확인**
   - 로봇이 "조용히 해"가 들어간 문장을 말하면 스스로 멈출 수 있다 (가능성은 낮음).
2. ③(VLM 이 보내는 `@quiet`)은 ① 이후 수십 ms 사이에 서버에 들어온 다른 말(gdm 위험 안내 등)도 함께 지운다.
3. 대화 모드 질문에 "조용히 해"가 들어가면(예: "여기 조용히 해야 되는 곳이야?") 질문이 아니라 정지로 처리된다.
4. **배포 순서**: TTS 서버를 먼저 바꾼다. 지금 서버는 `@quiet` 를 모르므로 일반 문장으로 보고 영문을 한글로 풀어 읽는다("@큐유아이이티"). 그래서 `enable` 은 서버 작업 완료를 확인한 뒤에 켠다.
   - VLM 의 ③ 도 같은 이유로 서버 작업이 끝난 뒤에 배포한다.
